# ポートフォリオ リファクタリング（提案 → 実装 → QA）

3つのサブエージェント（`portfolio-refactor-proposer` → `portfolio-refactor-coder` →
`portfolio-refactor-qa`）を、**メインの会話（あなた）が進行役として**順に呼び出す。
サブエージェントは他のサブエージェントを起動できないため、この進行はスキルを読んだ
メインの会話が担う。

**絶対条件**: 現在の見た目・エフェクト・動作を1つも変えない。軽くするために機能や演出を
削る施策は対象外。この条件に反する施策が出たら、その施策を外すかユーザーに確認する。

## 全体の流れとゲート（人間の承認が要る所）

```
[準備] → 1.提案 → ★ゲート1(提案の採否) → 2.実装 → 3.QA ─不合格→ 2.実装へ戻す（最大2回）
                                                    └合格→ ★ゲート2(結果確認) → 4.PR作成（マージは別途承認）
```

- ★ゲートでは必ず止まり、ユーザーの明示的な承認（「OK」等）を得てから先へ進む。
- 本番へ反映する `main` へのマージは、このスキルの範囲外。プロジェクトの CLAUDE.md の
  「マージ前の確認」に従い、PR作成とCI確認までで止める。

## 手順

### 0. 準備
- 作業ツリーの状態を `git status` で確認する。無関係な未コミット変更が他にある場合は、
  巻き込まないよう `git worktree add` で別の作業ディレクトリを切る。
- 作業ブランチを `main` から作成する（例: `work/<日付>-refactor-<内容>`）。
- **比較の基準点**として、変更前のコミットID（`git rev-parse HEAD`）を控える（QAが
  変更前後を比較するために使う）。
- 中間成果物（提案書など）は**リポジトリ内に置かず**、セッションのスクラッチ領域に
  保存する（公開リポジトリを汚さないため）。

### 1. 提案（portfolio-refactor-proposer）
- Agent ツールで `subagent_type: portfolio-refactor-proposer` を呼ぶ。プロンプトには
  対象（全体/特定ページ）とユーザーからの要望・制約を含める。
- 出力された提案書を、スクラッチ領域に `refactor-proposal.md` として保存する。

### ★ゲート1: 提案の採否
- 提案書の要点（施策一覧・優先順位・期待効果・エフェクトが壊れるリスク）を短くまとめて
  ユーザーに提示し、**どの施策を採用するか**を確認する（全部/一部/却下）。
- 承認された施策だけに絞った提案書を、実装への入力として確定する。

### 2. 実装（portfolio-refactor-coder）
- `subagent_type: portfolio-refactor-coder` に、**承認済みの提案書の全文**と、
  作業ブランチ・作業ディレクトリを渡す。
- 実装後、出力の「提案からの逸脱点」を確認する。逸脱が大きければQAへ進む前にユーザーへ共有する。
- 2回目以降（QAからの差し戻し）は、QAの指摘（エフェクト変化を最優先）を渡して修正させる。

### 3. 品質保証（portfolio-refactor-qa）
- `subagent_type: portfolio-refactor-qa` に、控えておいた**変更前コミットID**、承認済み
  提案書、実装エージェントの報告を渡す。
- 判定ルール:
  - **見た目・エフェクト・動作の変化が1件でもある** → 不合格。指摘をコーダーへ差し戻す。
  - 軽微な規約違反・過剰実装のみ → 内容をユーザーに報告して判断を仰ぐ（差し戻しは任意）。
  - 指摘なし → 合格。
- **差し戻しは最大2回まで。** 2回差し戻しても不合格なら、自動で続けず、状況（何が直らず
  残っているか）をユーザーに報告して指示を仰ぐ。

### ★ゲート2: 結果確認
- QAの結果、軽量化の効果（ファイルサイズ・行数などの前後比較の数値）、逸脱点を
  ユーザーに提示し、PR作成に進んでよいかを確認する。

### 4. PR作成
- プロジェクトの CLAUDE.md の「Git 自動化ルール」に従い、コミット→push→PR作成→CI結果確認まで
  行う。**マージはしない**（マージ確認のフォーマットで承認を求める）。
- CIの警告（画像サイズ・a11y・Lighthouse等）は、ジョブが成功していても必ず報告する。

## 補足
- 実装・QAの各段階では、`refactoring-playbook`（安全手順・影響範囲の確認・削除は確認を取る）と
  `portfolio-visual-check`（変更前後の撮影・検査）の手順に従う。PR作成は `portfolio-pr-flow` に従う。
- サブエージェントの種類（`portfolio-refactor-*`）は、Claude Code の**セッション開始時に**
  読み込まれる。作成・更新した直後のセッションで見つからない場合は、
  `.claude/agents/<名前>.md` を読み込んだ `general-purpose` エージェントに、その定義を
  役割指示として渡して代替する。
- 決定事項（採用した施策・見送った施策とその理由）は、PRの説明文に書き残す。
