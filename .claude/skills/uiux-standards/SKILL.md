# UI/UX 標準チェックリスト

このスキルは、UI 実装・変更時に満たすべき**客観的な品質基準**を定義する。
世界的に認知された標準（WCAG 2.2 / Nielsen の10ヒューリスティクス / Core Web Vitals / Apple HIG / Material Design）から、
検証可能な項目を抽出したもの。

- 表記ルール: **[必須]** = 違反したまま作業を完了してはならない ／ **[推奨]** = 原則守るが、正当な理由があれば逸脱可（理由をユーザーに説明すること）
- **チェック対象は変更箇所だけでなく、作業対象ページの既存実装も含む**。既存コードに違反を発見した場合は一覧で報告し、その場で安全に直せるものは修正、影響範囲が大きいものは修正方針を提案する。
- 美的方向性（配色・タイポグラフィの独自性）は `frontend-design` スキルが担当する。本スキルは**品質の下限**を保証する役割で、両者は併用する。

## 1. アクセシビリティ（WCAG 2.2 準拠）

- [必須] テキストのコントラスト比: 通常テキスト 4.5:1 以上、大きいテキスト（24px以上 or 太字19px以上）3:1 以上
- [必須] すべての意味のある画像に適切な `alt` 属性を付与（装飾画像は `alt=""`）
- [必須] キーボードのみで全機能が操作可能（Tab移動・Enter/Spaceで実行）
- [必須] フォーカスインジケーターを消さない（`outline: none` で消すなら代替の視覚表示を用意）
- [必須] セマンティックHTMLを使う: 見出しは `h1`〜`h6` を階層順に、ナビは `nav`、ボタンは `button`（`div` にclickを付けない）
- [必須] `<html lang="ja">` のように言語属性を設定
- [必須] フォーム入力には `label` を関連付ける
- [推奨] `prefers-reduced-motion` を尊重し、アニメーションを無効化できるようにする
- [推奨] 色だけで情報を伝えない（エラーは色＋アイコン/テキストで示す）

## 2. ユーザビリティ（Nielsen 10ヒューリスティクス）

- [必須] システム状態の可視化: 読み込み中・送信中・完了をユーザーに示す（無反応の時間を作らない）
- [必須] 一貫性: 同じ操作は全ページで同じ見た目・同じ場所・同じ名前にする（ナビゲーション・ボタンラベル等）
- [必須] エラーの防止と回復: 破壊的操作には確認を挟み、エラーメッセージは「何が起きたか＋どう直すか」を平易に書く
- [必須] 現在地の明示: ユーザーが今どのページにいるかわかるようにする（ナビのアクティブ表示等）
- [推奨] 認知負荷の削減: 選択肢や情報を一度に見せすぎない。重要なものから段階的に提示する
- [推奨] 外部世界との一致: システム都合の用語ではなく、ユーザーの言葉でラベルを書く

## 3. レスポンシブ / モバイル対応

- [必須] ビューポート幅 320px〜1920px で横スクロールが発生せず、レイアウトが崩れない
- [必須] タップ領域は最小 44×44px（リンク・ボタン・ハンバーガーメニュー）
- [必須] `<meta name="viewport" content="width=device-width, initial-scale=1">` を設定
- [推奨] モバイルファーストで書く（基本スタイル＝モバイル、`min-width` メディアクエリで拡張）
- [推奨] 画像は `max-width: 100%` で親要素からはみ出さないようにする

## 4. タイポグラフィ / 可読性

- [必須] 本文フォントサイズは 16px 以上
- [必須] 本文の行間（line-height）は 1.5 以上
- [推奨] 1行の文字数は日本語で 15〜35文字、英語で 45〜75文字程度に収める
- [推奨] 見出しと本文のサイズ差を明確にし、視覚的階層を作る

## 5. パフォーマンス（Core Web Vitals）

- [必須] LCP（最大コンテンツの描画）2.5秒以内を目標に、ヒーロー画像は圧縮・適切なサイズで配信
- [必須] CLS（レイアウトシフト）0.1以下: 画像には `width`/`height` 属性を付け、読み込みでガタつかせない
- [推奨] INP（操作への応答）200ms以内: 重いJavaScript処理でメインスレッドを塞がない
- [推奨] ファーストビュー外の画像には `loading="lazy"` を付与
- [推奨] 使っていないCSS・JS・ライブラリは読み込まない（依存を追加する前に本当に必要か検討）

## 6. 多言語対応（i18n）

- [必須] 各ページの `<html lang>` 属性を、そのページの主要言語と一致させる（日本語ページは `lang="ja"`、英語ページは `lang="en"`）
- [必須] 多言語版を提供する場合、すべてのページに言語切替の導線を同じ位置に設置し、切替後も同じ内容のページに着地させる
- [必須] 言語切替UIはテキストラベル（例: 「EN」「日本語」）で示す。国旗アイコンだけで表さない（国旗は国であって言語ではないため）
- [推奨] 対応言語ページ同士を `<link rel="alternate" hreflang="...">` で相互に指定する（検索エンジンに言語版の関係を伝えるため）
- [推奨] 言語による文章量の違い（日本語→英語で約1.5〜2倍に伸びることがある）でレイアウトが崩れないか、両言語で表示確認する
- [推奨] 日付・数値・固有名詞の表記は言語ごとの慣習に合わせる（例: 2026年7月2日 ⇔ July 2, 2026）

## 7. SEO・メタ情報（すべて推奨）

- [推奨] 各ページに固有の `<title>`（サイト名の使い回しにしない）と `meta description` を設定する
- [推奨] SNS共有用に OGP（`og:title`, `og:description`, `og:image`）を設定する
- [推奨] 見出し構造（h1は1ページ1つ）とセマンティックHTMLを保つ（1章・2章の項目がそのままSEOにも効く）

## 8. 実装後の自己検証手順

UIを変更したら、完了報告の前に以下を実施する：

1. 本チェックリストの [必須] 項目を、変更箇所および**作業対象ページの既存実装**に対して確認し、結果を報告に含める
2. 既存実装に違反を発見した場合は、修正したもの・提案に留めたものを分けて一覧報告する
3. ローカルサーバー（`python -m http.server 8080`）で実際の表示を確認する
4. 可能な環境ではスクリーンショットを取得し、モバイル幅（375px）とデスクトップ幅（1280px）の両方を確認する
5. 多言語ページに触れた場合は、全対応言語で同じ確認を行う
6. 逸脱した [推奨] 項目があれば、その理由をユーザーに説明する

## 9. このワークスペース（ポートフォリオ）固有の補足

汎用基準に加え、`portfolio/`（kentaro-sk.github.io）で作業する場合は以下を守る：

- GitHub Pages は静的ホスティングのため、サーバーサイド処理・ビルド工程を前提にしない（素のHTML/CSS/JSで完結させる）
- 既存スタック（jQuery 3.4.1 / ProgressBar.js / Font Awesome 4.7）の範囲で実装し、新しいライブラリ追加はユーザーに相談してから
- ページは「ディレクトリ + `index.html`」形式、ページ別CSSは `css/<ページ名>.css` に置く既存規約に従う
- スプラッシュアニメーション（`js/style.js`）はトップページ固有の演出として維持する
- 学術系ポートフォリオという性質上、奇抜さより信頼感・可読性を優先する
- 現状のサイトは日本語のみ。英語版を追加する際は本チェックリスト6章（多言語対応）に従い、日本語版と同一のページ構成にする
