# リファクタリング手順書（振る舞いを変えない整理）

**大原則: 外から見える結果（見た目・動作・出力）を変えない。** 変えたくなったら、それはリファクタリング
ではなく機能変更。別の作業として提案し、ユーザーの承認を得てから行う。

## 0. 始める前に
- 目的を1文で言えるようにする（例: 「重複したインラインstyleをクラスにまとめて、CSSを読みやすくする」）。
  目的があいまいなまま着手すると、整理のつもりで挙動を変えてしまう。
- 範囲を決める。**1回の作業で触るのは1つの関心事だけ**（例: 「CSSクラスの整理」と「画像の最適化」を
  混ぜない）。混ぜるとPRが読めず、問題が出たときに原因を切り分けられない。
- 無関係な未コミットの変更が作業ツリーにある場合は、巻き込まないよう別の作業ディレクトリ
  （`git worktree add`）で作業する。

## 1. 変更前の状態を記録する（あとで「変わっていない」と言える根拠）
- 見た目があるものは、**変更前のスクリーンショット**を撮る（`portfolio-visual-check` スキル参照）。
- 数値で残せるものは残す（行数・ファイルサイズ・クラスの使用回数・リクエスト数）。
- 静的チェックが今は通っていることを確認する（`npm run check:fast`）。壊れた状態から始めると、
  自分の変更が原因かどうか分からなくなる。

## 2. 小さく変える
- 1つの変更が1つの理由で説明できる大きさに保つ。目安は「1コミット＝1つの整理」。
- 変更のたびに検証する（後述）。まとめて大量に変えてからまとめて検証しない。
- 提案書や計画にない「ついでの改善」を混ぜない（過剰実装）。気づいたことは記録して、あとで別に提案する。

## 3. 共有されているものを変える前に、使用箇所を調べる（影響範囲）
- **共有クラス・共通関数・共通の値を編集する前に、必ず使用箇所を検索する**（`Grep`）。
  「このページだけのつもり」の変更が、同じクラスを使う他ページの見た目を壊す事故が最も多い。
- 使用箇所が1か所だけ、または特定ページだけの調整は、**共有クラスを書き換えず、その場のインライン指定
  （上書き）で済ませる**。
- 共通化は「同じものが**3か所以上**に現れたとき」に初めて検討する（過度な抽象化を避ける）。

## 4. 「使われなくなったもの」を洗い出す
- 整理の結果、参照されなくなったクラス・関数・変数・ファイルは、**その変更の中で一緒に整理する**
  （放置すると、あとで「使われているのか分からない」ものが増える）。
- 洗い出しは推測ではなく検索で行う。CSSクラスは全ファイルでの出現数、画像は `find-unused-assets` スキル。
- 動的に組み立てられる名前（文字列連結・テンプレートリテラル）は検索で見つからないことがあるので、
  「見つからない＝未使用」と決めつけず、生成側のコードも確認する。

## 5. 削除は「一覧を見せて、確認を取ってから」
- ファイル・大量のコードの削除は、**何を、なぜ、どこからも使われていない根拠つきで一覧にして
  ユーザーに提示し、明示的な許可を得てから**行う。無断で消さない。
- 削除はコミット単位で分け、あとから `git revert` で戻せるようにする。

## 6. 変更ごとの検証（「変わっていない」を確かめる）
1. **構文**: `npm run check:fast`（HTML・CSS）。
2. **見た目**: 変更前後のスクリーンショットを比較する（PC幅・スマホ幅）。差分があれば、意図した変更か
   崩れかを目視で判断する。スクロールで出現する演出は、完了まで待ってから撮る。
3. **動作**: クリック・ナビゲーション・フォームなど、触った箇所の操作を実際に行う。
4. **コンソールエラー・横はみ出し**が増えていないこと。
- 検証で「1つでも変わっている」と分かったら、軽量化などの効果に関係なく、それは不具合として直す
  （「軽くなったから多少の違いは許容」としない）。

## 7. まとめる
- 前後の数値（行数・サイズ・使用回数）を並べて、効果を数字で報告する。
- 決定事項（やったこと・見送ったこととその理由）を記録する（PR説明文、`decision-log`）。
- 公開リポジトリの場合、秘密情報・公開してはいけない固有名詞を書かない（フックが検知するが意識する）。

## このポートフォリオ固有の注意（`ws/personal/portfolio/`）
- **インラインstyleは基本的に許容**。同じstyle値が3か所以上で重複したときだけ、意味のあるクラス名に切り出して
  `css/site.css` に定義する（2か所以下はインラインのまま）。
- **クラス（`.c-XXX`）を編集する前に使用箇所の数を数える**。使われなくなったクラスは同じ変更内で削除する。
- **独自テンプレート構文**（`{{ identifier }}`）は、`onClick` などで識別子しか解決できず、インラインJSは書けない。
  クリック領域を広げたいときは、透明な `<a>` を重ねる「ストレッチリンク」方式にする（`<a>` の入れ子は不正なHTML）。
- **1辺だけトリミングしたい写真**は、内側の箱（縦横比とズーム位置）は変えず、固定高さの
  `overflow:hidden` の外枠で包む（調整済みの拡大率・位置の数値をいじらずに済む）。
- **`<div>` の閉じ忘れ**に注意。大きなブロックを差し替えたあとは `npm run check:html` で必ず確認する。
- **見た目に関わる方針**（サイズスケール・色・角丸・エレベーション）は `DESIGN.md` が正。変える場合は同時に更新する。
- 複数のサブエージェントで提案→実装→QAを回す大規模な軽量化は `portfolio-refactor` スキルを使う。
