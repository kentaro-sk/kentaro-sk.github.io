# 未使用アセットの洗い出し

`images/` と `fonts/` 配下のファイルのうち、HTML・CSS・JS のどこからも参照されていないものを一覧にする。
**このスキルは削除しない。** 削除の判断はユーザーがする。

## 手順

### 1. 一覧を作る
プロジェクト直下で実行する:

```
node scripts/find-unused-assets.mjs        # 人が読む形式
node scripts/find-unused-assets.mjs --json # 機械可読
```

出力は3区分:
- **未使用候補**: どこにもパスもファイル名も現れない。
- **要確認**: パスは無いが、ファイル名だけが現れる／そのディレクトリを動的に組み立てるコードがある。
- （使用中のものは出力しない）

### 2. 候補ごとに裏を取る（スクリプトの判定を鵜呑みにしない）
- `git log --oneline -3 -- <path>` で、いつ・なぜ追加されたか、最近参照が外れたのかを確認する
  （例: 直近の変更で画面から外した写真の実体が残っているだけ、というケースが典型）。
- 「要確認」は、生成側のコード（文字列連結・テンプレートリテラル）を読んで、実際に使われうるか判断する。
- 別ブランチや未マージのPRで使われていないか、必要なら `git grep <ファイル名> $(git branch -r)` で確認する。
- 実行時にしか決まらないパス（外部データ由来）は静的検索では見つからない。該当しそうなら候補から外す。

### 3. ユーザーに一覧を見せる（削除の前に必ず）
次の形式で提示し、**どれを削除してよいか**の明示的な許可を得る:

| ファイル | サイズ | 根拠（どこからも参照されていない／最後に参照が外れたコミット） |
|---|---|---|

- 合計で何MB減るかも添える。
- 許可が出るまで**1ファイルも削除しない**。全部/一部/なし、をユーザーが決める。

### 4. 許可された分だけ削除する
- `git rm <path>` で削除し、**削除だけのコミット**にする（あとで `git revert` で戻せる）。
- 削除後に `npm run check:links`（リンク・画像パス切れ）と `npm run check:fast` を実行し、
  参照切れが出ていないことを確認する。
- PR の説明に、削除したファイルの一覧と根拠を書く。

## 補足
- 1MB を超える画像は CI の警告対象（`npm run check:images`）。未使用でなくても、最適化（圧縮・WebP化）の候補になる。
  画質に関わる判断なので、圧縮は必ず変更前後を見比べてユーザーに確認する。
- 参照元として読むのは `.html` / `.css` / `.js` / `.json` / `.svg`。Markdown（README等）は「説明」であり
  実際の使用ではないため対象外。
